# 浏览器 UI 适配计划

**分支**：`feat/browser-ui-adaptation`  
**范围**：浏览器 chrome / 桌面与平板布局；不改海报分页算法、不做曲库云同步、不做完整 PWA（可另开）。

关联诊断：相对 Capacitor 手机壳，当前 Web 是同一套满屏竖屏 UI 的投影。

---

## 1. 产品目标（桌面编辑页）

| 场景 | 期望 |
|------|------|
| **桌面编辑（始终）** | **两页并列**：左 = 歌词原文；右 = **笔记本页**（有无笔记都显示） |
| 右侧空状态 | 空白笔记本样式 + 引导文案，促使用户划词并做笔记 |
| 右侧有内容 | 已存划词笔记列表 / 详情；AI 查询结果在笔记本页内展示（或顶层叠在笔记本工作区） |
| 手机 / 窄屏 | 保持现有：单栏歌词 + AI 底抽屉；笔记可读（见 §3.7） |

「两页」指编辑工作区的双栏阅读布局，**不是**导出分页的两张海报。  
**关键决策**：右栏**不依赖**「是否已有笔记 / 是否打开 AI」才出现——桌面一进编辑就是左右平放。

---

## 2. 现状与差距

### 2.1 已有能力

- `≥900px` 且 `edit-area--explain`：显微镜才与画布横向并列（右侧约 `min(380px, 38vw)`）。
- 划词笔记 DOM：`.shufuri-explain-note` **内嵌在** `bodyHtml` 歌词流中，点选后用全屏浮层编辑。

### 2.2 差距

1. 默认桌面仍是**单栏**歌词居中；无常驻右栏笔记本。
2. 右栏仅在 AI 打开时出现，且偏窄侧栏，不是对等「笔记本页」。
3. 空状态缺少「空白笔记本 + 划词引导」。
4. 笔记编辑仍是全屏遮罩，未纳入右栏。

---

## 3. 桌面双栏方案（核心）

### 3.1 断点

**`min-width: 900px`**（token：`--edit-split-min: 900px`）。  
`< 900px`：不启用双栏；行为与现网一致。

### 3.2 始终并列的布局

```text
┌──────────────── edit-area（桌面 ≥900px，始终） ──────────────┐
│ toolbar …                                                    │
│ ┌──────────── workspace (row, ~1:1) ───────────────────────┐ │
│ │  Left「歌词页」              │  Right「笔记本页」         │ │
│ │  · 原文 + 假名/译文          │  · 空：空白本 + 划词引导   │ │
│ │  · 独立纵向滚动              │  · 有：笔记卡片列表/详情   │ │
│ │  · 隐藏内嵌 note 块          │  · AI：在本页内展示查询    │ │
│ │  · 合理栏宽与 scale          │  · 独立纵向滚动            │ │
│ └─────────────────────────────┴────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

左右视觉对等（约 **50:50**，或 52:48），均满高、可独立滚动；不是「主内容 + 窄侧栏」。

### 3.3 左栏「歌词页」

- 仅展示歌词原文（标题、假名、译文等海报正文），**不展示**内嵌 `.shufuri-explain-note`（双栏时 CSS 隐藏或镜像过滤）。
- 编辑预览继续用 `mobilePoster` **内容规格**（分页/导出不变）；屏上 `displayScale` 封顶为 **B5 正文基线 12px 的 1:1**（`elasticFontBase * scale ≈ 12`），避免宽屏把 32px 手机稿撑成巨大字。
- InkToolbox 锚定左栏右缘。

### 3.4 右栏「笔记本页」（始终存在）

#### 空状态（无划词笔记、无打开的 AI 会话）

呈现**空白笔记本**视觉（纸感底、浅线/装订暗示等，贴合现有 SHUFURI 克制风格，避免花哨）：

- 引导文案示例方向：
  - 「在左侧划选词语」
  - 「本地释义即时出现；需要时点 AI讲解」
  - 「写入后笔记会出现在这一页」
- 可附轻量 CTA：提示开启划词模式（若当前未开），不打断阅读。

#### 有已存笔记

- 以笔记本页内分区列表展示：**重点词汇** / **重点语法** / **划词笔记**（数据均来自 `bodyHtml`，单源）。
- 每条可点选编辑；右上角小 **×** 删除（样式对齐左侧 `shufuri-*-delete`）。
- 桌面左栏隐藏 `.lyrics-vocabulary` / `.lyrics-grammar`，避免双边重复。

#### AI 查询进行中 / 面板打开

- 显微镜内容在**右栏笔记本工作区**内展示（升级为页级宽度，替换当前 ~380px 侧栏）。
- 与笔记列表关系：同一右栏内切换或上下分区（「本次查询」在上 / 「本页笔记」在下；或 Tab）。默认：有进行中的查询时优先展示查询。

### 3.5 数据与导出

- 持久化仍只写 `bodyHtml`（含 note）；右栏是视图层。
- 保存 / 导出 / 手机打开：完整 HTML 不变；窄屏仍可在正文流中看笔记（或沿用现浮层）。

### 3.6 非目标

- 双栏 ≠ 导出 PDF 两页。
- 不改分页装箱算法。
- 不强制桌面编辑改用 B5 画布规格。

### 3.7 窄屏降级

- 单栏歌词；笔记可仍在正文或浮层；AI = 底抽屉。
- 不展示常驻空白笔记本（避免小屏浪费纵向空间）。

## 4. 其余浏览器适配（摘要）

### P0

1. Web 放宽缩放；原生壳可继续禁缩。  
2. 收缩全局 `user-select: none`。  
3. 桌面保存可发现（右键文案 +「保存本页」）。  
4. 微信内下载兜底。

### P1

5. 首页/抽屉壳层断点。  
6. `pointer: fine` 细滚动条。  
7. 波轮桌面点击选中。  
8. Web「从剪贴板填入」。  
9. **§3 桌面始终双栏 + 空白笔记本引导**（本文件核心）。

### P2

10. `dvh` 统一、hover/active 分端、词卡详情加宽、Web vs Native 能力表。

## 5. 建议实现分期

| Phase | 内容 |
|-------|------|
| **A** | P0 可用性 |
| **B** | ✅ 桌面始终双栏壳：左歌词 + 右空白笔记本空状态 |
| **C** | ✅ 右栏接入已存笔记列表；左栏隐藏内嵌 note（编辑仍用浮层） |
| **D** | ✅ AI 显微镜迁入右栏页级展示 |
| **E** | P1 其余 + P2（待做） |

**验收（桌面 ≥900px）**

- [ ] 一进编辑即左右两页，**无笔记时右栏仍为空白笔记本 + 划词引导**。  
- [ ] 左侧仅歌词原文，栏宽与字号舒适。  
- [ ] 写入划词笔记后，出现在右栏；左栏不重复堆笔记块。  
- [ ] 打开 AI 后，查询在右栏内展示，不改为底抽屉（桌面）。  
- [ ] 保存后手机/导出仍含完整笔记 HTML。  
- [ ] `<900px` 与现网一致。

## 7. 一句话

桌面编辑页**始终**左右平放：**左歌词原文，右空白笔记本**；笔记本用空状态引导划词做笔记，有内容后再填满同一右页（含 AI 查询），窄屏保持单栏。
