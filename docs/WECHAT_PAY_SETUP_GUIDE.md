# 微信扫码登录 + 微信扫码支付（Native）开通步骤文档

> 目标：在桌面 Web 站点（SHUFURI）上，用「微信开放平台网站应用」做扫码登录确认会员身份，用「微信支付商户号 Native 支付」做订阅收款。
> 适用场景：主使用场景为电脑桌面端浏览器，用户扫码（登录码 + 支付码）完成登录与付款。
> 本文档只讲**资质注册与后台开通步骤**，不含代码实现（代码骨架见后续文档）。

---

## 0. 前置硬性条件

| 条件 | 说明 | 能否绕过 |
|---|---|---|
| **企业主体** | 营业执照 + 对公银行账户 | ❌ 不能。个人主体无法开通微信支付虚拟商品收款，也没有 UnionID 机制 |
| **同一企业主体** | 开放平台账号 与 微信支付商户号 建议用同一家公司 | ⚠️ 强烈建议。否则登录 UnionID 与支付 openid 无法天然打通，会员绑定需额外映射 |
| **备案域名** | 网站应用回调、支付回调需公网 HTTPS 域名 | ❌ 不能。微信要求可访问的 HTTPS 回调地址 |

**结论**：先确认你已有「企业营业执照 + 对公账户 + 已备案域名」，否则后续全部阻塞。

---

## 1. 注册顺序总览

两件事**互不冲突，可同时发起**，但都依赖企业认证，且都需 3–7 个工作日：

```
① 微信开放平台（open.weixin.qq.com）企业认证
        └─ 创建「网站应用」→ 拿到 AppID + AppSecret（用于扫码登录）
                    │
② 微信支付商户号（pay.weixin.qq.com）企业认证
        └─ 申请 API 证书 + 开通 Native 支付 → 拿到 mchid / APIv3密钥 / 证书
                    │
③ 把上述密钥配置进 CloudBase 环境变量（绝不写进代码）
                    │
④ 联调（需代码骨架就绪后）
```

---

## 2. 第一步：微信开放平台（扫码登录）

### 2.1 注册并企业认证
1. 打开 `https://open.weixin.qq.com`。
2. 注册账号，进入「账号中心 → 开发者资质认证」。
3. 提交企业营业执照、对公账户信息，缴纳认证费（300 元/年）。
4. 等待审核（通常 1–3 个工作日）。

> ⚠️ **只有企业认证的开放平台才有 UnionID 机制**，个人主体没有。UnionID 是你跨「登录 / 支付」统一用户身份的关键。

### 2.2 创建网站应用
1. 进入「管理中心 → 网站应用 → 创建网站应用」。
2. 填写：
   - **网站名称**：如「SHUFURI」。
   - **网站域名**：你的已备案域名（如 `shufuri.com` 或 CloudBase 托管域名）。
   - **网站回调域名（redirect_uri）**：登录后微信回跳的地址，必须是该域名下的 HTTPS 地址，例如 `https://shufuri.com/auth/wx/callback`。
   - 应用图标、简介等。
3. 提交审核（1–3 个工作日）。
4. 审核通过后，在「网站应用详情」拿到：
   - **AppID**（网站应用 AppID）
   - **AppSecret**（点击「重置/查看」，妥善保存）

### 2.3 记录关键信息
| 变量名（后续用） | 来源 | 示例 |
|---|---|---|
| `WX_OPEN_APPID` | 网站应用详情 | `wx1234567890abcdef` |
| `WX_OPEN_SECRET` | 网站应用详情 | `a1b2c3...`（32位） |

---

## 3. 第二步：微信支付商户号（Native 扫码支付）

### 3.1 注册并企业认证
1. 打开 `https://pay.weixin.qq.com`。
2. 注册商户号，主体类型选「企业」，提交营业执照、对公账户。
3. 完成**对公账户打款验证**（微信会打一小笔钱到你填的对公账户，回填金额验证）。
4. 等待审核（通常 1–5 个工作日）。
5. 审核通过后拿到 **mchid（商户号）**，形如 `1900000000`。

> ⚠️ 主体务必与开放平台**同一企业**，否则 UnionID 与支付 openid 无法打通。若已用不同主体，需在成员管理中做「关联」或后期做 openid 映射。

### 3.2 设置 APIv3 密钥
1. 商户平台 → 「账户中心 → API 安全」。
2. 设置 **APIv3 密钥**：自己生成一个 32 位随机字符串，妥善保存（用于解密支付回调报文）。
3. 记录为 `WXPAY_APIV3_KEY`。

### 3.3 申请 API 证书（非常重要）
1. 商户平台 → 「账户中心 → API 安全 → API 证书」。
2. 点击「申请证书」，按引导生成（或在本地用微信提供的工具生成证书请求）。
3. 申请成功后下载：
   - **`apiclient_key.pem`**：商户私钥（用于给请求做 RSA 签名）。
   - 证书 **序列号 `serial_no`**（证书详情里可见）。
4. 记录：
   - `WXPAY_PRIVATE_KEY`：私钥 `apiclient_key.pem` 的**完整文本内容**。
   - `WXPAY_SERIAL_NO`：证书序列号。

> 🔒 私钥和 APIv3 密钥等同于"钱箱钥匙"，只能存进 CloudBase 环境变量 / 密钥管理，绝不能提交进代码仓库。

### 3.4 开通 Native 支付产品
1. 商户平台 → 「产品中心 → 我的产品」。
2. 找到「Native 支付」（扫码支付），点击「申请开通」。
3. 按提示填写产品信息，提交审核（一般较快）。
4. 开通后，Native 支付可用于「桌面网页展示支付二维码，手机微信扫码付款」。

### 3.5 配置支付回调地址（notify_url）
1. 在调用下单接口时传入 `notify_url`（也可在产品/API 配置里预设）。
2. 该地址必须是**公网 HTTPS**，指向你后续的云函数域名，例如：
   `https://your-env.ap-shanghai.app.tcb.qcloud.la/wxPayNotify`
   （具体域名在你部署云函数后由 CloudBase 提供，见第 4 节）。
3. 微信支付会在用户付款后，向该地址 POST 加密的支付结果。

### 3.6 记录关键信息
| 变量名（后续用） | 来源 | 示例 |
|---|---|---|
| `WXPAY_MCHID` | 商户平台首页 | `1900000000` |
| `WXPAY_APIV3_KEY` | 账户中心 → API 安全 | 32位随机串 |
| `WXPAY_SERIAL_NO` | API 证书详情 | `ABCDEF1234...` |
| `WXPAY_PRIVATE_KEY` | `apiclient_key.pem` 全文 | `-----BEGIN PRIVATE KEY-----...` |

---

## 4. 第三步：配置 CloudBase 环境变量

等 2、3 两步拿到全部密钥后，在 CloudBase 控制台配置（不要写进代码）：

1. 打开 CloudBase 控制台 → 当前环境（`ai-native-d5gtc59uc47601f23`）→ 「云函数 / 环境变量」或「环境配置 → 环境变量」。
2. 新增以下变量：

| 变量名 | 值 |
|---|---|
| `WX_OPEN_APPID` | 网站应用 AppID |
| `WX_OPEN_SECRET` | 网站应用 AppSecret |
| `WXPAY_MCHID` | 商户号 |
| `WXPAY_APIV3_KEY` | APIv3 密钥 |
| `WXPAY_SERIAL_NO` | 证书序列号 |
| `WXPAY_PRIVATE_KEY` | 私钥 pem 全文（含换行，用多行值存储） |

3. 确认云函数的公网 HTTPS 域名（CloudBase 云函数默认提供），把 `wxPayNotify` 的域名填回商户平台的 `notify_url`。

---

## 5. 合规与类目提醒 ⚠️

- **虚拟商品（会员/订阅）收款**：商户号经营类目需选允许虚拟商品的类目（如「文娱」「咨询服务」等）。部分类目需提供《增值电信业务经营许可证》，按微信审核要求准备。
- **桌面 Web 收款不受苹果 IAP 限制**：IAP 仅限 App Store 上架的 app；Web 站点用微信收款可正常使用。
- **不能使用小程序虚拟支付规则套 Web**：Web 收款走的是「微信支付商户号 + Native 支付」，与小程序的支付文档不同，别混淆。
- **沙箱测试**：正式收款前，建议先用微信支付沙箱 / 测试参数跑通下单→扫码→回调→写库全流程。

## 6. 注册期间可并行准备的事项（不等代码）

- [ ] 准备企业营业执照扫描件 + 对公账户信息（开户行、账号）
- [ ] 确认已备案域名（登录回调 + 支付回调都要用）
- [ ] 注册微信开放平台并完成企业认证
- [ ] 创建网站应用，拿到 AppID / AppSecret
- [ ] 注册微信支付商户号并完成认证 + 对公打款验证
- [ ] 设置 APIv3 密钥
- [ ] 申请 API 证书，保存 `apiclient_key.pem` 与 `serial_no`
- [ ] 开通 Native 支付产品
- [ ] 确定支付回调域名（CloudBase 云函数 HTTPS 域名）
- [ ] 将上述 6 个密钥填入 CloudBase 环境变量

---

## 7. 完成判据（何时可以开始联调）

当且仅当以下全部满足，即可进入代码联调阶段：

1. ✅ 开放平台网站应用已审核通过，持有 `WX_OPEN_APPID` / `WX_OPEN_SECRET`
2. ✅ 微信支付商户号已认证，持有 `WXPAY_MCHID`
3. ✅ 已设置 `WXPAY_APIV3_KEY`、申请 `apiclient_key.pem` 与 `serial_no`
4. ✅ Native 支付产品已开通
5. ✅ 6 个 CloudBase 环境变量已配置
6. ✅ `notify_url` 已指向可达的云函数 HTTPS 域名

达到以上条件后，即可对接云函数 `wxLogin` / `createWxOrder` / `wxPayNotify` 与前端登录/订阅组件（见后续代码文档）。

## 附：常见坑清单

| 坑 | 后果 | 规避 |
|---|---|---|
| 用个人主体 | 无法开通微信支付虚拟收款、无 UnionID | 必须用企业主体 |
| 开放平台与商户号主体不一致 | 登录 UnionID 与支付 openid 不互通 | 同一企业注册两者 |
| 私钥/APIv3 密钥写进代码 | 密钥泄露、资金风险 | 仅存 CloudBase 环境变量 |
| notify_url 非 HTTPS 或非公网 | 收不到支付回调，会员不开通 | 用 CloudBase 云函数 HTTPS 域名 |
| 类目不符 | 审核被拒、收款受限 | 选允许的虚拟商品类目并备齐资质 |
| 混淆小程序支付与 Native 支付 | 接入文档用错、调不起 | Web 用 Native 支付（JSAPI 商户 Native 下单） |
